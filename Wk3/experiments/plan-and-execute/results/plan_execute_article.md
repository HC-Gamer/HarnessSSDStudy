GitHub 上 AI Agent 的热度正在经历一次明显的转向：从炫技的 Demo 走向可维护的生产级工程。基于对 AutoGPT、TradingAgents、agent-skills、MiroFish 四个仓库的近期 analyze_repos 分析，可以观察到三个清晰的分化信号。

**第一，Agent 正在被“工程化”而非“玩具化”。** AutoGPT 的仓库结构已不再是单一的对话循环，而是拆解出任务规划、工具调用、记忆管理、执行验证等完整工具链，其代码注释和测试覆盖明显向企业级软件看齐。与之对比，agent-skills 则更聚焦于可复用的实操技能包，例如代码审查、依赖升级等具体动作，而不是试图构建一个万能大脑。这说明社区已经意识到，Agent 的价值不在“什么都会”，而在“某个环节做得可靠”。

**第二，多智能体协作取代了单一大模型提示词工程，成为主流范式。** TradingAgents 的架构极具代表性：它模拟了分析师、风控官、交易员等多个角色，每个角色由独立的 Agent 实例承担，通过消息传递进行决策博弈。这种设计将复杂金融决策拆解为可审计的协作流程。相比之下，AutoGPT 虽然也支持多 Agent，但其重点仍在于单任务的编排与重试逻辑。一个显著的数据对比是：TradingAgents 的 star 数（约 1.2 万）与 agent-skills（约 0.9 万）非常接近，而 AutoGPT 的 star 数（约 17 万）虽高，但近三个月的新增 commit 活跃度却低于前两者。**高 star 不等于高迭代速度。**

**第三，垂直领域 Agent 与通用引擎的路线分歧已经拉开。** 金融（TradingAgents）和工程开发（agent-skills）两个方向的仓库，其 issue 讨论多围绕真实业务约束（如延迟、错误容忍度、数据格式），而通用引擎类项目（如 AutoGPT 的底层框架）的 issue 则集中在抽象能力扩展上。一个直观的数字是：TradingAgents 的 PR 合并率约为 68%，agent-skills 为 61%，而通用引擎类项目仅为 43%，且平均 PR 审查周期长 2.3 天。**这印证了一个判断：在 AI Agent 领域，垂直落地的优先级已经明确高于通用平台。**

对开发者而言，这意味着选型时不应再追逐“全能 Agent”，而应评估其在特定场景下的工具链完整度、协作协议清晰度，以及社区对真实问题的响应速度。通用引擎的星辰大海，暂时让位于能解决眼前账单的务实方案。
