## 正文

最近在翻 Hacker News 的时候，一条 2011 年的预测帖把我拉住了：原帖声称自己的 URL 会在 11 年后失效。137 分、55 条评论，热度远超同期的技术新闻。大家讨论的不是代码，而是数字遗产的脆弱性。这让我想到，我们整天在谈 AI Agent 编排，谈多智能体协作，却很少问一个问题：**Agent 的“记忆”和“上下文”能活多久？**

这周 arXiv 上两篇论文恰好戳中了这个痛点。一篇提出了 MIST 基准，专门测试模型在“误导上下文”下能否保持正确回答——四种条件：干净、误导、正确、无关。另一篇则给了个数据：39-45% 的数据科学家时间耗在特征工程上。两者一对照，结论很清晰：**Agent 的可靠性，不取决于模型多聪明，而取决于它如何筛选和信任上下文。**

现在主流的编排框架，比如 LangGraph、AutoGen、CrewAI，都在解决一个问题：怎么让多个 Agent 分工、传递信息、共享状态。但它们默认了一个前提——上下文是可信的。可现实是，Agent 拿到的上下文，可能来自一个 11 年前的 URL，可能来自一个被篡改的日志，也可能来自另一个 Agent 的错误输出。MIST 基准的 SC2W 指标就是在量化这种“选择性信任”能力：一个什么都不信的模型，和一个什么都信的模型，都不如一个知道什么时候信、什么时候不信的模型。

我觉得，编排框架的下一个分水岭，不是谁的工具链更全，而是谁能让 Agent 学会“怀疑”。就像那个 11 年前的预测帖——URL 会失效，但真正的洞察不会。我们的 Agent 编排框架，也该在“上下文管理”里内置一层“失效检测”和“信任评估”，而不是把所有信息都当真理喂给模型。

否则，再复杂的编排，也只是在精心搭建一座沙堡，潮水一来，什么都没了。
