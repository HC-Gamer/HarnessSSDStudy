## 关键要点

- MIST 基准将每个推理项目渲染为 4 种条件（干净、误导、正确上下文、无关上下文），用于量化模型的选择性信任能力，例如对比误导与干净条件下的准确率差异。
- SC2W 配对指标统计误导信号被忽略的次数，直接衡量模型在对抗性上下文中的鲁棒性，弥补了单纯训练模型抵抗信号可能导致其忽略所有上下文的缺陷。
- EHR 特征工程占数据科学家 39-45% 的工作量，对比规则方法和 LLM 方法，论文提出证据链接管道以整合碎片化数据，针对心衰（影响美国 670 万成年人）进行特征提取。
- Long Bets 预测帖子（2011 年发布）在 Hacker News 获得 137 分和 55 条评论，但其原始 URL 将于 11 年后失效，引发对长期链接稳定性的讨论。
- Microsoft Word for Windows 1.1a 原生 x64 移植项目获 61 分、19 评论，对比原始 16 位版本，该移植旨在解决现代 64 位系统上的兼容性问题，例如直接调用 Win32 API 而非模拟层。

## 正文

我盯着这个采集结果看了半天，第一反应是：这期内容太散了，像是一锅乱炖。但转念一想，这种看似无主题的散点分布，恰恰暴露了当前 AI 工程化进程中最真实的一个侧面——大家都在各自战壕里解决具体问题，而问题之间，其实暗藏着一根共同的线：**我们到底该在什么时候信任模型，又该在什么时候信任系统？**

真正让我眼前一亮的是那篇关于选择性上下文偏好优化的论文。它提出的 MIST 基准把同一个推理问题渲染成四种条件——干净、误导、正确上下文、无关上下文——然后用准确率的差值来量化一个模型“什么时候该信、什么时候该怀疑”。这个设计太聪明了，因为它不是在考模型的知识储备，而是在考模型的“判断力”。更妙的是那个 SC2W 配对指标，它统计的是模型在误导信号面前“忍住不跟”的次数。这直接戳中了一个长期被忽视的痛点：我们训练模型抵抗误导信号，结果它连正确的上下文也一并忽略了，变成了一个过度防御的偏执狂。这个指标就是在逼模型学会“精准信任”。

另一篇关于 EHR 特征工程的论文也很有意思，它说数据科学家 39%-45% 的时间都花在特征工程上——这个数字我一点都不惊讶，因为我自己就干过这事儿，真的是在碎片化、脏乱差的医疗数据里捞针。论文提出的证据链接管道，本质上就是想用 LLM 把这块硬骨头啃下来，针对心衰（美国 670 万成年人受影响）做特征提取。这让我想：我们天天讨论模型能力、上下文窗口、推理成本，但真正的瓶颈往往不在模型，而在数据管线。

至于 Hacker News 上那个 2011 年的 Long Bets 帖子，137 分、55 条评论，讨论的却是原始 URL 将在 11 年后失效——这就像是在提醒我们，AI 模型会过时，链接也会死，但好的想法和好的讨论，它们的价值是跨时间的。Word 1.1a 的 x64 移植也是一样，一个 30 年前的软件，在今天被重新编译成原生 64 位，直接调用 Win32 API 而不是模拟层，这不也是一种“选择性信任”吗？信任底层系统，而不是信任一个兼容层。

所以，这期内容虽然散，但拼起来看，你会发现整个 AI 生态正在从“堆能力”转向“建信任”。模型不再只是越大越好，它需要知道什么时候该听谁的；系统不再只是越快越好，它需要知道自己依赖的是什么。这才是真正值得深入的方向。
