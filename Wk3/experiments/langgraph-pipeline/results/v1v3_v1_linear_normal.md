## 正文

最近 Red Hat 的一篇技术文章让我重新审视了 CPU 在 LLM 推理中的角色。他们提出将部分注意力计算放回 CPU，而非一刀切全交给 GPU，这在延迟和成本上带来了意外惊喜。纯 GPU 方案在资源利用率上确实存在瓶颈，而 CPU 的并行潜力被严重低估了。这提醒我们，架构优化不应只盯着显存带宽，更该回归计算本质——任务切分比硬件堆叠更值得投入。

另一边，OpenAI 对 Hugging Face 的意外攻击事件被 Simon Willison 梳理成完整时间线，社区讨论热度高达 82 条评论。这次事件暴露的不仅是安全漏洞，更是 AI 供应链中“默认信任”的脆弱性。我们依赖的预训练权重、数据集和推理服务，每层都可能成为攻击面。与其事后修补，不如在编排框架里内置验证机制，比如哈希校验和来源追溯。

亚马逊新数据中心将配备美国污染最严重的发电厂，这消息在 118 条评论里炸开了锅。AI 的能耗账不该只算 GPU 电表，还要算上冷却、制造和电力基础设施的隐性排放。对比其他数据中心采用可再生能源的策略，亚马逊的选择显然短视。作为开发者，我们或许该在模型效率优化上多花功夫——更小的模型、更聪明的调度，比无限堆算力更可持续。

Nixpkgs 核心团队解散的消息让我有些唏嘘。治理分歧和倦怠是开源项目的常见死因，但 Nix 生态的独特性和影响力让这次解散格外刺眼。对比 Linux 内核的层级化治理，Nix 的扁平结构虽然灵活，却缺乏缓冲机制。长期维护和发布节奏的不确定性，可能会让依赖 Nix 的 CI/CD 和可复现实验环境陷入被动。

最后，arXiv 上那篇关于选择性上下文信任的论文提出了 SC2W 指标和 MIST 基准，专门衡量模型在误导性上下文下的表现。传统鲁棒性训练倾向于忽略所有上下文，但这样会丢失有用信息。SC2W 的巧妙之处在于，它让模型在 clean 和 misleading 条件下都能保持准确率，而不是简单粗暴地“一刀切”。这种细粒度的信任机制，或许会成为未来 Agent 编排中处理多源信息的关键。
