V1 的三个痛点——为什么需要自动化？
痛点 1：人驱动 — 代码生成靠 OpenCode，但每步还要你发起对话触发
•   忘了触发 → 数据断更；依赖人驱动 → 效率低、容易遗漏


痛点 2：无质量检查 — 产出直接入库，没有质量门卫
•   JSON 格式错误 → 下游解析失败
•   必填字段缺失 → 信息不完整
•   摘要空洞无物 → 知识库价值归零


痛点 3：无反馈循环 — 出了问题不知道，知道了也不自动修
•   开环系统：输入 → 处理 → 输出 → （无人检查）
•   没有“感知→判断→纠正”的自动回路


核心问题：如何让 Agent 自己检查、自己纠错？

什么是 Hook？事件触发的自动化代码

Hook = 在特定时机自动执行的代码
•   不需要你手动调用 — 事件发生时自动触发
类比：常见的 Hook：
•   Git Hooks — commit 前自动跑 lint（pre-commit）
•   CI/CD Pipeline — push 后自动跑测试（GitHub Actions）
•   React Hooks — 组件渲染后自动执行副作用（useEffect）
Agent 场景的 Hook：
•   Agent 要执行工具前 → 自动检查权限（tool.execute.before）
•   Agent 写完文件后 → 自动校验格式（tool.execute.after）
•   Agent 完成任务前 → 自动做最终质量检查（Stop）


本质：把人工检查变成自动检查

OpenCode Plugin Hook 体系 — 真实 API

插件位置：.opencode/plugins/*.ts（TypeScript 文件，自动加载）
包名：@opencode-ai/plugin（注意不是 @opencode/plugin）


核心 Hook 事件（实际支持的）：
• tool.execute.before — 工具执行前触发（可拦截）
• tool.execute.after — 工具执行后触发（可校验产出）
• chat.message             — 收到消息时触发
• command.execute.before — 命令执行前触发
• shell.env             — 注入环境变量


Plugin 签名（真实 API）：
    export const MyHook: Plugin = async ({ $ }) => {
        return { "tool.execute.after": async (input) => { ... } }
    }
•       → 不是 definePlugin()，是直接导出 Plugin 类型的函数
Hook 详解 — tool.execute.before：权限门卫

触发时机： Agent 准备调用工具时，在实际执行前触发
• 用途： 拦截危险操作、检查权限、修改参数


实战场景：
•   Agent 想删除文件 → before Hook 检查路径
•   → 如果是 knowledge/ 目录 → 拦截，返回警告
•   → 如果是 /tmp/ 临时文件 → 放行
•
类比： 大楼门卫
•   快递员要进大楼（Agent 要执行工具）
•   门卫检查工牌（before Hook 检查权限）
•   有工牌 → 放行 | 没工牌 → 拦截


本节课重点不在 before，而在 after
•   因为我们的场景是'写完文件后校验'，不是'写之前拦截'

 // Stop Hook：Agent 停止前做最终质检
 // 确保所有知识条目都通过了质量校验

 export function onAgentStop(event: StopEvent) {
  const { context } = event;

     // 检查本次任务是否涉及知识库操作
     if (!context.task.includes('knowledge')) {
       return { allow: true };
     }

     // 运行 Python 质量校验脚本
     const result = exec(
        'python scripts/validate_json.py knowledge/raw/'
     );

     if (result.exitCode !== 0) {
       return {
          allow: false, // 阻止 Agent 停止
          feedback: '质量检查未通过，请修正以下问题：\n'
                + result.stderr
       };
     }

     return { allow: true }; // 通过，允许停止
 }

空洞用词黑名单 — AI 最爱用的空话

为什么要检测空洞用词？
•   AI 生成的文本天然倾向于使用模糊的、积极的、无信息量的表达
•   知识库要的是事实和数据，不是营销文案
黑名单词汇（示例）：
•   非常强大 → 改为：支持 50+ 平台的编排调度
•   令人印象深刻 → 改为：推理速度比 GPT-4 快 3 倍
•   颠覆性的创新 → 改为：首次实现端到端多模态推理
•   革命性 → 改为：将训练成本降低了 90%
•   业界领先/ 遥遥领先'→ 改为：GitHub Star 数超过 10 万
检测规则：
•   每命中 1 个黑名单词 → 扣 0.3 分（满分 1.0）
•   命中 3 个以上 → 该条目直接标记为“需要重写”


原则：用事实替代形容词，用数字替代感叹号

工程思想总结卡：反馈驱动循环
一句话 — Agent 系统的可靠性不来自执行能力，而来自反馈循环

为什么重要：
• 没有反馈循环的系统是开环的 — 错误会累积、扩散、不可控
• 有反馈循环的系统是闭环的 — 错误会被检测、修正、收敛


本节验证：
• tool.execute.before — 执行前拦截危险操作（预防错误）
• ool.execute.after — 执行后校验产出质量（发现错误）
• Stop — 停止前最终质检（兜底检查）
• Python 脚本 — 独立可用的校验工具（多场景复用）


通用原则（超越 AI 编程）：
• 任何工程系统要可靠运行，都需要反馈循环
• 代码有测试、工厂有质检、飞机有仪表 — 同一个原理
• 从'做了'到'做对了' — 差的就是一个 Verify 节点
