CI/CD 基本概念

• CI — Continuous Integration（持续集成）
•   代码一提交，自动构建、自动测试——有问题立刻发现


• CD — Continuous Delivery（持续交付）
•   测试通过后，自动部署到生产环境——人工审批一下就上线


• 对我们的知识库项目来说：
•   CI = 每天自动采集数据 + 自动校验格式
•   CD = 采集结果自动提交到仓库 + 自动更新知识库


• GitHub Actions = 免费的云端自动化平台
•   不需要自己买服务器，GitHub 提供运行环境
•   公开仓库完全免费，私有仓库每月 2000 分钟免费额度

手动触发分析 — workflow_dispatch + 本地运行

 # ── 方式 1：GitHub 页面手动触发 ──────────────────────
 # Actions → Daily Knowledge Collection → Run workflow
 # 点击按钮即可触发完整流程（含 AI 分析）

 # 在 yml 中添加输入参数：
 on:
  workflow_dispatch:
    inputs:
      run_analysis:
        description: "Run AI analysis (Step 3-4)?"
        type: boolean
        default: false

 # Step 中判断是否运行分析：
 - name: Run AI analysis
  if: inputs.run_analysis == true
  run: python pipeline.py --step 3 --step 4
  env:
    DEEPSEEK_API_KEY: ${{ secrets.DEEPSEEK_API_KEY }}

 # ── 方式 2：本地直接运行 ────────────────────────────
 python pipeline.py --step 3 --step 4
GitHub Secrets 配置 — 安全管理 API Key

• 为什么需要 Secrets？
• API Key 不能写在代码里——推送到 GitHub 就泄露了
• Secrets 加密存储，只有 Actions 运行时才能读取


• 配置步骤：
• 1. 打开 GitHub 仓库 → Settings → Secrets and variables → Actions
• 2. 点击 New repository secret
• 3. Name 填 DEEPSEEK_API_KEY，Value 填你的 API Key
• 4. 点击 Add secret


• 在 workflow 中使用：
• env: DEEPSEEK_API_KEY: ${{ secrets.DEEPSEEK_API_KEY }}


• 安全原则：
• Secret 一旦保存，无法再查看原始值（只能删除重建）
• Fork 仓库不会继承 Secrets——即使仓库公开，Key 也安全

监控与告警 — 如何知道自动化是否正常运行？

• 1. GitHub Actions 运行状态
• 仓库 → Actions 标签页 → 查看每次运行的状态（绿色/红色）
• 点击具体运行 → 查看每个 Step 的日志输出


• 2. 邮件通知（默认开启）
• Workflow 失败时，GitHub 自动发邮件通知仓库 Owner
• Settings → Notifications → Actions 可调整通知策略


• 3. Badge 状态徽标
• 在 README.md 中添加 Badge，实时显示 Workflow 状态
• ![status](https://github.com/USER/REPO/actions/workflows/daily-collect.yml/badge.svg)
•
• 4. 自定义告警（进阶）
• 在 Workflow 最后加一个 Step，失败时发 Slack/钉钉通知
• 用上节课学的 MCP 连接外部通知渠道
V1 → V2 对比 — 从编码自动化到采集自动化的跨越

V1：编码自动化（OpenCode/AI Code）   V2：编码自动化（Hooks/定时作业）
用 AI 编码搭建 Agent + Skill 骨架   GitHub Actions 定时触发
人驱动：每天打开终端运行 pipeline        pipeline.py 自动执行采集
人检查：手动查看输出结果                 Hooks 自动校验数据格式
人提交：手动 git commit + push     自动 commit + push 到仓库


AI 帮你写代码，但执行靠人驱动             机器永不忘记，24/7 运行
忘了就断了，没有连续性                  数据连续积累，形成时间线


Agent × 3（采集/分析/整理）          自动采集 + 手动分析
每次执行 ~5 分钟人工操作               人工操作 → 0 分钟/天

  V4
                   [Bot 服务]                          推送Bot/Telegram/飞书

创建 .github/workflows/daily-collect.yml，配置 schedule 定时触发。推送到 GitHub 后检查 Actions 页面是否正

任务 3：（可选）添加每周摘要生成
创建 weekly-digest.yml，每周日定时运行。使用 opencode run 的 headless 模式生成周摘要。需要
配置 DEEPSEEK_API_KEY（或其他大模型 API Key）到 GitHub Secrets。验证产出的 Markdown 摘
要质量——是否有趋势分析、是否有具体数据支撑。
