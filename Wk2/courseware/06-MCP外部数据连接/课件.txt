实战选择：MCP vs Python 直接调 API

 MCP 方案                     Python Pipeline 方案
 AI 动态决策用哪个工具               代码直接调 API，不需要 AI
 适合交互式探索场景                  适合确定性流水线场景
 你说"搜一下"，AI 自己选 Server      urllib/requests 调 GitHub API


 优势：灵活、标准化、可扩展              优势：零 Token 成本、快速、可控
 劣势：每次调用都消耗 Token           劣势：需要写代码、不够灵活
     采集 30 条 = 30 次 AI 决策         采集 30 条 = 1 次 API 调用
     成本高、速度慢、不可控                  纯 Python，零 AI 成本


 适合：需要 AI 判断的场景             适合：知识库采集这种固定流程

 import xml.etree.ElementTree as ET

 RSS_FEEDS = [
   "https://hnrss.org/best?count=20",

 def collect_rss(limit: int = 30):
    """Step 2: 采集 RSS 订阅（纯 API，零 LLM 成本）"""
    items = []
    for feed_url in RSS_FEEDS:
       xml_data = urllib.request.urlopen(feed_url).read()
       root = ET.fromstring(xml_data)
       for entry in root.iter("item"):
          items.append({
              "title": (entry.findtext("title") or "").strip(),
              "url": (entry.findtext("link") or "").strip(),
              "desc": (entry.findtext("description") or "")[:500],
              "date": (entry.findtext("pubDate") or "").strip(),
              "source": feed_url.split("/")[2],
          })
    return items[:limit]

 import xml.etree.ElementTree as ET                             scripts/rss_reader.py | python
 import urllib.request

 RSS_FEEDS = {
   "hn_best": "https://hnrss.org/best?count=20",
   "lobsters": "https://lobste.rs/rss",
   "hf_papers": "https://huggingface.co/papers/rss",
   # 自定义 RSS 源可以随时添加
 }

 def fetch_rss(feed_name: str) -> list[dict]:
    """通用 RSS 读取器（纯 Python，零 LLM 成本）"""
    url = RSS_FEEDS[feed_name]
    xml_data = urllib.request.urlopen(url).read()
    root = ET.fromstring(xml_data)

   items = []
   for item in root.iter("item"):
      items.append({
          "title": (item.findtext("title") or "").strip(),
          "url": (item.findtext("link") or "").strip(),
          "desc": (item.findtext("description") or "")[:500],
          "date": (item.findtext("pubDate") or "").strip(),
          "source": feed_name,
      })
   return items
多源采集策略：GitHub + RSS = 双路采集

• 三路数据源，全部免费：
•   GitHub Search API — AI/LLM/Agent 热门项目（认证后 30 次/分钟）
•   RSS Feeds — 任意订阅源（HN Best、Lobsters、HF Papers...）
•
• 免费 vs 付费分离（核心设计原则）：
•   Step 1-2：纯 API 采集 → 零成本（Python urllib）
•   Step 3：AI 深度分析 → 有成本（DeepSeek ~0.02 元/30 条）
•   Step 4：整理入库 → 零成本（Python 字符串处理）
•
• 每日运行成本估算：
•   采集 60 条（GitHub 30 + RSS 30） = 免费
•   AI 分析 60 条 ≈ 0.04 元（DeepSeek） / 0.2 元（Qwen）
•   一个月 ≈ 1.2 元 ~ 6 元，比一杯咖啡便宜

工程思想总结卡

• MCP = 标准化连接协议
•   Client ↔ Server 架构，OpenCode 内置支持
•   三种传输：stdio（本地） / SSE（远程流式） / HTTP（标准请求）
•   适合需要 AI 动态决策的交互式场景
• Python Pipeline = 实战利器
•   确定性流程用代码，不需要 AI 决策
•   model_client.py 统一模型客户端，一键切换国产模型
•   pipeline.py 四步流水线：采集 → 采集 → 分析 → 入库
• 免费采集 + 付费分析 = 成本最优
•   Step 1-2 纯 API 零成本，Step 3 调 LLM 有成本
•   每日 60 条分析 ≈ 0.04 元，每月不到一杯咖啡
•   核心原则：能用代码解决的就不用 AI
