Token 基础知识

• 什么是 Token？ — 大模型处理文本的最小单位，不是字也不是词
•
• 中文： 1 个汉字 ≈ 1.5-2 tokens（取决于模型的分词器）
•   「人工智能」4 个字 ≈ 6-8 tokens
• 英文： 1 个单词 ≈ 1-1.5 tokens
•   “artificial intelligence”2 词 ≈ 3-4 tokens


• 输入 Token vs 输出 Token：
•   输入 Token — 你发给模型的内容（system prompt + 用户消息）
•   输出 Token — 模型生成的回复内容
•   关键：输出 token 通常比输入 token 贵 2-4 倍！
•
• 为什么要了解 Token？
•   因为 API 按 token 计费，不按次数计费
•   同样调一次 API，100 tokens 和 10000 tokens 差 100 倍

成本速算公式

• 基础公式：
•   单次成本 = (输入 tokens + 输出 tokens) × 单价


• 实际案例 — 用 DeepSeek-V3 分析一篇技术文章：
•   输入：system prompt 500 tokens + 文章内容 2000 tokens = 2500 tokens
•   输出：摘要 + 亮点 + 评分 ≈ 500 tokens
•   成本 = 2500 × ¥0.000001 + 500 × ¥0.000002 = ¥0.0035
•
• 一句话记忆法：
•   用 DeepSeek 做一次完整分析 ≈ ¥0.003-0.005
•   约等于三分钱的千分之一
•   换句话说：分析 1000 篇文章才花 3-5 块钱


• 成本直觉： 单次调用极便宜 → 关键是控制调用次数和 token 量

缓存策略 — 减少重复消耗

• 原则： 相同的输入不要重复调用模型


• AGENTS.md 缓存优势：
•   AGENTS.md 内容稳定 → system prompt 不变 → 模型可复用 KV Cache
•   DeepSeek 等模型支持 prompt caching，重复的前缀部分享受折扣
• 数据采集层面：
•   增量采集 vs 全量采集 — 只处理新数据
•   文件指纹（hash）判断内容是否变化 — 没变化就跳过
•   上次采集的 ID 列表 → 这次只分析新增的
• 结果缓存：
•   分析结果写入文件 → 下次先检查缓存文件是否存在
•   缓存有效期：24 小时（每日采集场景）
• 经验数据： 缓存策略可减少 40-70% 的 token 消耗
Prompt 优化 — 减少 Token 消耗的 4 个技巧

• 技巧 1：精简 system prompt
•   删除冗余描述 → 2000 tokens 压缩到 500 tokens
•   用结构化指令替代长段落 → 每次调用省 1500 tokens


• 技巧 2：约束输出格式
•   要求输出 JSON 而非长文 → 输出 token 减少 60-80%
•   “只输出 JSON，不要解释” → 一句话省几百 tokens


• 技巧 3：批量处理 vs 逐条处理
•   10 条数据一次性发送 → 省 9 次 system prompt 开销
•   权衡：batch 太大可能降低质量 → 建议 5-10 条/批


• 技巧 4：分层提问
•   第一轮：用免费模型做粗筛（符合/不符合）
•   第二轮：只对通过粗筛的数据用付费模型做深度分析
