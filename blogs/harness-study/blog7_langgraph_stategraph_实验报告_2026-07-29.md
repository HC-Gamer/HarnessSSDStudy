# 我给 Harness 加了个"智能"路由，然后它一次都没用上 (2026-07-29)

> 用 LangGraph StateGraph 重写线性 sub-agent 管线。三个实验，质量分全部 100/100，零重写，成本不到一分钱。
> 这不是成功案例。这是一份失败报告——而最有价值的部分，恰好是失败本身。

我花了一周，给管线加上条件路由和反馈循环，让它能在质量不达标的时候自己回炉重做。

然后我跑了三轮，三次都走了直线。

更难堪的是后来我发现的：那道我引以为傲的质量门禁，在结构上根本关不上；而那条从未被走过的回边，藏着一个会让整个循环失去意义的语义 bug。**如果它哪怕被走过一次，我当场就会发现。正因为它一次都没被走过，我在报告里写下了"已实现自动重写循环"。**

这篇讲的就是这两件事。

## 我想解决的问题

Week 2 我做的是一条三段式管线：`collector → analyzer → organizer`。三个 Agent 各有独立权限矩阵，靠文件系统传递中间产物。

跑起来是稳的，但有两个绕不开的限制。**一是没有运行时分支**：管线是 must-pass 的，摘要好还是烂，organizer 一视同仁地归档。**二是没有回头路**：我发现质量不行，唯一的办法是人工重跑整条管线——检测在我脑子里，决策在我手上，修复靠我敲命令。

这两件事本质是同一件：管线里没有"判断"的位置。所以我用 StateGraph 重写了它。

## 我造了什么

图本身只有几行声明：

```python
builder.add_edge(START, "search")
builder.add_edge("search", "analyze")
builder.add_edge("analyze", "quality_check")

builder.add_conditional_edges(
    "quality_check", decide_route,
    {"rewrite": "rewrite", "organize": "organize"},
)
builder.add_edge("rewrite", "analyze")   # 回边：反馈循环
builder.add_edge("organize", END)
```

节点函数退化成最纯粹的形态——收 state，返回 partial dict，由框架合并。控制流从函数调用的嵌套关系里被抽出来，变成了一张可以单独拿出来看、单独修改、单独讨论的声明表。

这个解耦是真实的收益，我不否认。我要调路由逻辑，只动 `decide_route` 那五行和边声明，五个节点函数一行不碰。

但代价也是真实的：`PipelineState` 里十三个字段，任何节点都能读写。`analyze_node` 写 `quality_score`，`quality_check_node` 读它写 `should_rewrite`，`decide_route` 再读 `should_rewrite`——这条链是隐式的，图上完全看不见。**图画出来的是控制流，藏起来的是数据流。**

V1 用文件传递的时候，谁读谁写是明摆着的，边界是物理隔离的。换成共享 dict 之后，边界消失了，只能靠自律维持。我现在越来越怀疑，全局共享 state 在节点多起来之后就是个新的全局变量问题——只不过它长得像框架特性，所以没人管它叫全局变量。

## 三条路，三条直线

三个主题跑完，实际拓扑是：

```
START → search → analyze → quality_check → organize → END
```

没有分支，没有循环。和 V1 的线性管线**完全同构**。

质量分全是 100，重写次数全是 0。如果我在这里收尾，这会是一篇很顺的报告：图编排跑通了，质量全满，成本可以忽略。

但这三个数字里，最刺眼的是**零重写**。

## 这道门检测的不是质量，是解析失败

`analyze_node` 里的评分是这么算的：

```python
quality_score = min(100, max(0, 60 + len(summary) // 5 - (3 - len(key_points)) * 10))
```

prompt 要求"80-120 字摘要 + 5 条要点"，模型照办了。代进去：`60 + 24 + 20 = 104`，被 `min` 截成 100。

就算模型只给出 prompt 的下限——80 字、3 条要点——也是 `60 + 16 - 0 = 76`。门槛是 60。**这道门在结构上就关不上。**

我一开始的结论停在这儿：评分函数没有区分度。但顺着代码追下去，我发现了更难看的东西。这个分数唯一能跌破 60 的路径，是这里：

```python
try:
    data = json.loads(result)
except json.JSONDecodeError:
    data = {"summary": result[:100], "key_points": []}   # ← 只有这条路能不及格
```

解析失败 → `key_points` 变空 → `60 + 20 - 30 = 50` → 触发 rewrite。

也就是说，我这道"质量门禁"检测的根本不是质量，是**模型有没有吐出合法 JSON**。我以为自己写了个质检员，实际上写的是个语法检查器，还给它挂了"质量"的牌子挂了一周。

## 那条从没走过的边，是坏的

因为 rewrite 分支一次都没进过，藏在里面的问题就一直没暴露。

```python
def rewrite_node(state):
    # 带着反馈重新生成更高质量的分析
    return {
        "summary": new_summary,                         # 改进后的摘要
        "quality_score": state["quality_score"] + 20,   # 加 20 分
        "rewrite_count": state["rewrite_count"] + 1,
    }

builder.add_edge("rewrite", "analyze")   # ← 问题在这
```

回边指向 `analyze`。而 `analyze_node` 是**从 `raw_content` 从头重新分析**的，它压根不读 `summary`，也不读 `quality_score`。

所以 rewrite 辛辛苦苦生成的改进版摘要、那 +20 分，回到 analyze 之后被**完全覆盖**。整条循环真正生效的，只有 `rewrite_count += 1` 那个防死循环的计数器。

我实现的不是"带反馈的重试"，是**原地重摇三次骰子**。

根子在更早的地方。线性管线里，任何变量在任何时刻只有一个值；加了回边之后，`summary` 的含义变成了"最近一次分析的结果"，它的历史被覆盖了。我写 rewrite 时脑子里想的是"带着反馈重做"，但反馈的载体是什么？是上一版的 summary——而它马上就要被这一版覆盖。我对这件事的处理方式是加了个 `rewrite_count` 计数器，**用一个标量代替本该存在的一段历史**。

循环引入的不是"再来一次"，是**时间维度**。这是线性管线天然免疫、而我在画图的时候完全没意识到的东西。

## 我今天学到的

真正的收获不在"我做出了图编排"，在"我设计的东西为什么没被用上"。

**第一，没有被触发过的代码路径，等于不存在的代码路径。** 它比"没写"更危险——"没写"是诚实的空白，"写了没跑过"会让我停止思考，误以为已经有个机制在替我守着。上面那个覆盖 bug 是纯逻辑错误，读一遍代码就能看出来，但我读了一周都没看出来，因为报告里那个 100 分让我以为这块没问题。

**第二，度量本身需要被度量。** Week 2 我的教训是"hook 会忠实执行我写错的标准"，这周我又犯了一次，而且更彻底——上周分数至少还有分布，这周直接恒定满分。一个恒定输出的度量，信息量是零。而我搭了检测、决策、修复三个环节，唯独没花力气验证**检测本身有没有分辨力**。

**第三，我的结论可能只是实验设计的 artifact。** 三个主题、每个一轮，用这个样本量去论证"图编排在实践中退化成线性"，本身就不成立。如果把公式修好跑三十轮，触发率是零、三成还是九成，指向三个完全相反的下一步——而我现在没有任何数据能区分它们。

所以下一步不是把门槛从 60 提到 90，那只是换个数字继续自欺。是构造一条必然不及格的输入，逼这台车拐一次弯。**先证明闸门能关上，再去调它关的位置。**

我花了一周造了一台能拐弯的车，开了三趟直路，然后在报告里写"转向系统工作正常"。

九次调用花了不到一分钱，我找那个 bug 花了半小时。真正稀缺的从来不是 token。
