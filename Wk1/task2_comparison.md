# 裸 API vs OpenCode 对比体会（实操实验报告）

## 实验过程

- **裸 API 调用**：写了 60 行 Python 脚本，手动构造 HTTP 请求、拼 prompt、读文件、解析 JSON。API 返回很快（~7-10s），但 AI 在测试 1 中说"请提供项目目录结构"——它无法感知文件系统，只能泛泛而谈。测试 2 我手动读文件塞进 prompt，AI 才给出代码分析。每一轮都是孤立的，没有上下文延续。

- **OpenCode 编排**：一句话命令 `opencode run "请分析 /tmp/task2_sample.py"`。从输出日志可见 `→ Read /tmp/task2_sample.py`——它自动识别了文件路径并读取注入。分析结果结构化、基于实际文件内容、按分类给出表格。同样的问题，OpenCode 能得到具体分析，因为编排器替模型感知了环境。

## 关键差异

1. **文件感知**：裸 API 完全不知道文件存在，需要手动 open()+拼 prompt；OpenCode 自动发现路径、读取文件、注入上下文
2. **上下文延续**：裸 API 每调用完一切归零，想追问得自己维护 messages 数组；OpenCode 自动保留历史
3. **操作复杂度**：裸 API 要写脚本、处理错误、解析输出；OpenCode 一句话完成任务
4. **输出形式**：裸 API 返回原始 JSON 需解析；OpenCode 直接输出格式化 Markdown

## 我对「无状态推理」和「有状态编排」的理解

无状态推理就像每次给同一个陌生人写一封完整的信——你必须交代全部背景，对方也只能根据你写的内容回答，无法主动查阅任何资料。有状态编排则像和一个驻场的分析师协作——你说一句话，它自己去看文件、跑命令、根据结果思考，还可以追问。核心区别不是模型变强了（底层是同一个模型），而是编排层在模型外围构建了「感知-行动-更新状态」的循环，把一次次孤立的 API 调用连成了持续的协作。这个循环，就是 Agent 的本质。
