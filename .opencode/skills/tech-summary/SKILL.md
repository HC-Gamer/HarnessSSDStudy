# 技术内容深度分析技能

## 使用场景
在知识库分析阶段，对采集到的原始数据进行价值评估。当用户要求"分析这些项目"、"打标签"、"写摘要"、"给评分"时自动触发。

## 执行步骤

### 第 1 步：读取最新采集数据
读取 `knowledge/raw/` 目录下最新的 `github-trending-*.json` 文件。

### 第 2 步：逐条深度分析
对每条数据执行以下操作：

**摘要**：中文，不超过 50 字
**技术亮点**：2-3 个，用事实和数据说话（如"Python 实现，42K stars"）
**评分**：1-10 分，附具体理由
**标签建议**：1-3 个标签

### 第 3 步：趋势发现
从整体数据中识别：
- 共同主题（如"多 Agent 框架"、"本地推理"）
- 新概念和方向
- 技术栈偏好

### 第 4 步：输出分析结果

```json
{
  "source": "github-trending",
  "analyzed_at": "2025-07-13T00:05:00Z",
  "trends": ["多 Agent 框架持续火热", "本地推理成为焦点"],
  "items": [
    {
      "name": "owner/repo",
      "summary": "中文摘要 <= 50 字",
      "highlights": ["亮点 1（含数据）", "亮点 2"],
      "relevance_score": 8,
      "score_reason": "评分理由",
      "tags": ["tag1", "tag2"]
    }
  ]
}
```

## 评分标准
| 分数 | 含义 | 示例 |
|------|------|------|
| 9-10 | 改变格局 | 突破性技术或行业标准项目 |
| 7-8 | 直接有帮助 | 实用工具，值得试用 |
| 5-6 | 值得了解 | 有亮点但有限制 |
| 1-4 | 可略过 | 不相关或质量低 |

## 约束
- 15 个项目中 9-10 分不超过 2 个（防止评分膨胀）
- 不自写文件，由下游 Organizer 处理
