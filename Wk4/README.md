### 这意味着什么

Wk4 **不是** Wk3 的技术纵深延续，而是一次**换赛道**：
从「把 Agent 编排好」转向「把 Agent 做成一个有读者的产品」。

```
Wk1 能搭起来      Wk2 能自动跑      Wk3 能编排复杂流程   Wk4 能上线给人用
────────────     ────────────      ─────────────────   ────────────────
Memory 工程       Hooks 事件驱动     StateGraph 图编排    OpenClaw 入门
Sub-Agents 分工   MCP 外部数据       条件路由/反馈循环     内容输出与分发
Skills 封装       CI/CD 定时触发     checkpoint 恢复      读者互动 Bot
裸 API vs 框架    成本控制           质量门禁 + 熔断       部署上线与运维
   │                 │                  │                   │
   ▼                 ▼                  ▼                   ▼
AGENTS.md         V2 自动化管线      V3 StateGraph 管线    V4 上线的产品
specs/ SDD        成本可计量         质量可门禁            **有读者、有分发、有运维**
```

前三周的产出是**给自己看的实验**；Wk4 第一次要求产出**面向外部读者**。
知识库从「每天采集入库」变成「每天采集 → 生成内容 → 分发出去 → 读者能互动」。

## 7. 两条从前三周带过来的纪律

**一、指标看起来完美的时候，先怀疑指标。**
Wk3 首轮报告写着「三次实验质量分全部 100/100」，读起来像大获成功，
实际是评分函数坏了——基线 60 分正好等于门槛 60 分，任何正常产出都必然及格。
这个 bug 活了十天，因为结果太漂亮，没人想去代入一遍公式。
做法：每个评分函数都配**已知好 / 已知坏**样本集，先证明有区分度再拿去评真实产出。

**二、"验证过了"要能追到一条真的执行记录。**
`Wk2/experiments/v1-pipeline/sub-agent-test-log.md` 写着三个 Agent 的权限矩阵
「全部符合预期」。2026-08-08 查出来：那次「测试」跑的是
`run_v1_pipeline.py` —— 一个**硬编码假数据、完全不经过 OpenCode** 的 Python 模拟。
真跑一次立刻实测越权 7 次。
Wk4 要上线给读者看，这类「纸面验证」的代价会从丢面子变成丢数据。
做法：报告里每个「✅ 已验证」，都要能指到一条日志、一个断言、或一份产出文件。
