### 为什么推断是「评估 + 生产化」

三条线索指向同一个方向：

1. **能力曲线已经走完「能用」**。Wk1 解决「Agent 怎么搭起来」（Memory、Sub-Agent、Skill），
   Wk2 解决「怎么自动化并控住成本」（Hooks、MCP、CI/CD、成本），
   Wk3 解决「怎么编排复杂流程」（图、条件路由、反馈循环、checkpoint）。
   按「能用 → 可靠 → 能上线」的顺序，剩下的就是**可靠性度量与上线**。

2. **Wk3 自己撞到了评估的墙**。Wk3 实验最大的发现是「质量分公式无区分度」——
   一个坏掉的评估函数让三次实验全部报告 100/100，反馈循环从未触发。
   修复轮换了公式后仍有残留问题：**及格区内评分饱和，能判「过/不过」但不能给及格产出排序**。
   这个缺口写在 `Wk3/.../EXPERIMENT_REPORT.md` 的「残留问题 #1」，明确标注为「留给 Wk4 评估专题」。

3. **《Agent 设计模式之美》的框架里，治理与可观测性是「外圈」**。
   `ADP学习索引.md` 记录的纵轴七脉是：内圈（感知/记忆/推理/行动，让 Agent **能用**）、
   中圈（反思，让 Agent **可靠**）、外圈（协作/治理，让 Agent **能上线**）。
   索引里还留了一句「没有治理就没有好 Agent」，并把「治理可观测性/审计/状态账本」
   标为**反复暴露却尚未系统解决的技术债务线**。Wk4 处在课程尾部，正对应外圈。

## 一条经验，从 Wk3 带过来

Wk3 首轮报告写着「三次实验质量分全部 100/100」，读起来像大获成功，
实际是评分函数坏了——**基线 60 分正好等于门槛 60 分，任何正常产出都必然及格**。
这个 bug 活了十天，因为运行结果太漂亮，没人想去代入一遍公式。

Wk4 如果真的做评估，第一条纪律应该是：**指标看起来完美的时候，先怀疑指标。**
具体做法是每个评分函数都配一组**已知好/已知坏**的样本，让它先在样本上证明自己有区分度，
再拿去评真实产出（`Wk3/.../quality.py` 的 `SCORING_SAMPLES` 就是这么做的，
`python quality.py` 可以直接看到新旧公式的分布对比）。
